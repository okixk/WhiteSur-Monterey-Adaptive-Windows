## A larger beta update: editable tabs

This release moves from the 0.1 beta series to **0.2** because it changes how the browser's main toolbar works. The selected tab now becomes Firefox's native address/search field. It stays open while selected, including the native search selector, security controls, page actions, and suggestions.

### What's new

- Selected tabs adapt from **300 px with room to spare to 260 px when crowded**. Background tabs shrink from 180 to 88 px before scrolling.
- Fixed stale address-field placement and shifting tabs during rapid Ctrl+W, Ctrl+T, and tab switching. Tab insertion/removal uses Firefox's complete non-animated paths.
- Kept the layout update scheduled after native tab scrolling, including when a synchronous tab-close layout runs first.
- Kept Adaptive Tab Bar Color compatibility through Firefox's existing theme variables, with light/dark colour checks.
- Added a user-local Firefox runtime, profile-specific desktop launchers, update support, diagnostics, and owned-launcher removal on uninstall.
- Fixed [issue #4](https://github.com/okixk/WhiteSur-Monterey-Adaptive-Windows/issues/4): the search-engine icon, engine name, and close button now stay centred within the address field in both layouts.
- Fixed the classic desktop toolbar reservation for fresh profiles with the default sidebar toggle, preventing tabs from covering the address field.

### Installation and upgrade

1. Download the Windows theme ZIP attached below and extract it.
2. Fully close Firefox and run `Install.cmd`.
3. Open the new **WhiteSur Firefox - &lt;profile&gt;** desktop shortcut.

**The new launcher matters:** editable tabs require the AutoConfig loader in the user-local Firefox copy. Opening the original Firefox program gives the classic adaptive CSS toolbar. The original installation is preserved, and no administrator rights are required. Existing `customChrome.css` is preserved on update; the installer backs up an existing chrome folder.

Editable tabs require **Firefox 158+ with horizontal tabs**. Older Firefox and detected existing AutoConfig conflicts use the classic layout; vertical tabs leave the editable-tab script inactive. `-ClassicToolbar` explicitly selects the CSS-only installation. Close Firefox before switching binaries for the same profile. See [setup details](https://github.com/okixk/WhiteSur-Monterey-Adaptive-Windows/blob/v0.2.0-beta.1/docs/EDITABLE-TABS.md).

### Validation

Tested on Windows 11 with Firefox 158.0.1 using separate disposable profiles and a Firefox copy installed by the actual installer. Native checks cover editable-tab navigation, rapid keyboard switching/closing, crowded windows, pinned tabs, private windows, adaptive colour variables, and search-engine pill alignment and closing in editable/classic layouts. Installer checks cover install/update/uninstall, preserved custom CSS and unrelated preferences, binary upgrades without downgrades, ownership checks, and compatibility fallbacks. The existing classic layout and package suites are retained.

Local results: **25 editable-tab checks, 18 search-mode checks, 27 Windows installer checks, and 16/16 package groups passed**. All 15 classic responsive widths and the r7/r8/r9 regression suites also passed.

This remains a prerelease. The browser UI uses Firefox internals, and custom toolbar extensions or future Firefox versions may require adjustments. Shared runtime copies are retained on uninstall for other installed profiles.
